# بوصلة — ملخص Portfolio للإصدار المحلي الأول

## شرح مبسط لعبدالله

بوصلة تساعد شخصًا يفكر في المجالات الرقمية على البدء: يجيب عن أنشطة يحبها، يرى مجالات مع سبب اقتراحها، يجرب نشاطًا قصيرًا، ثم يختار مهارة وخطوة تعلم. لا تقول له «أنت مناسب لهذه المهنة»، ولا تقيس جاهزيته للتوظيف. أسماء المهارات وأوصافها من إطار رسمي؛ أسئلة الاهتمامات وربطها والأمثلة وتمارين البداية اجتهاد تحريري ظاهر للمستخدم.

المشروع بدأ بتحليل العاملين في القطاع الخاص، ثم أضيفت رحلة بوصلة. تحليل العاملين بقي مكونًا منفصلًا؛ لا يدخل في ترتيب المجالات. التصميم الحالي اعتمده عبدالله للإصدار الأول، ولم تُجرَ دراسة مع مستخدمين أو قياس لنتائج التعلم.

## English CV description

**Saudi Career Compass — a local Arabic exploration and learning-planning application that turns official digital-sector skill documents into an explainable journey from interests to a fictional hands-on activity and a first learning step. Built with Python and vanilla JavaScript, with validated source ingestion, local scheduled refresh, and recoverable progress import/export.**

## Evidence-based CV bullets

- Built an Arabic RTL exploration workflow with 11 interest questions, four interactive fictional demonstrations, explainable field suggestions, and optional self-assessment using Python, HTML, CSS, and JavaScript ES modules.
- Integrated validated XLSX/PDF/CSV ingestion with source hashes, staged atomic publication, last-known-good recovery, and locally scheduled source checks with overlap prevention.
- Implemented backward-compatible, previewed progress import/export with conflict validation and recovery backups; verified browser journeys, keyboard and motion behavior, narrow-screen layouts, and failure cases in isolated Edge profiles.

هذه صياغات عن وظائف منفذة، لا عن عدد مستخدمين أو أثر مقاس. الأعداد الفعلية للاختبارات وقيودها في `RELEASE-INTEGRATION.md`؛ لا تُذكر «مراجعة مستقلة نهائية» لأن الوكيل نفسه نفذ وتحقق من الدمج.

## كيف تنتقل البيانات

1. روابط ومعرّفات مصادر محددة في `compass/config.py`.
2. الجلب يفحص الاستجابة والتوقيع وبنية الملف ويخزن النسخ بالبصمة والسجل، ويحتفظ بآخر نسخة سليمة.
3. البناء يحول المهارات والمجموعات وإثبات المصادر إلى JSON في مجلد مرحلي؛ بعد التحقق يُعتمد جيل بيانات وبيان معًا.
4. خادم محلي على 8620 يقدم ملفات الواجهة والبيانات. JavaScript يحسب الاقتراحات من إجابات المستخدم الفعلية بمنطق ظاهر، دون إرسال إجاباته إلى الخادم.
5. التقدم في التخزين المحلي؛ ملف الاستعادة يجمع تقدم المستكشف وسجل التقييم الموسع المستقل دون تحويل السُّلّم أو دمج إجابات متعارضة.

## قرارات يمكن شرحها في مقابلة

- لماذا JavaScript دون إطار: رحلة قصيرة، RTL، تحكم في الإتاحة، ولا خطوة بناء للواجهة؛ Python مخصص لخط البيانات والخادم المحلي.
- لماذا الاحتفاظ بعنوان 8620: التخزين تابع للأصل، والاحتفاظ بالأصل ومفاتيح المستكشف يحافظ على التقدم السابق.
- لماذا لم ندمج التقييمين: تقييم المستكشف بسُلّم تحريري مبسط، والتقييم القديم بسُلّم رسمي وأهداف؛ تحويلهما تلقائيًا قد يعطي معنى خاطئًا للجواب.
- لماذا المفقود ليس صفرًا: «لا أعرف» والتخطي غير مقيّمين؛ صفر صريح يعني أن المستخدم اختار «لم أبدأ»، فلا يصح اختلاق تقييم له.
- لماذا نشر مرحلي ومؤشر ذري: البيانات والبيان يُعتمدان كنسخة واحدة؛ فشل الجلب أو البناء أو الكتابة لا يخرج نسخة نصف مكتملة للمستخدم.
- لماذا مراجعة بشرية للفترات: أسماء وفترات المصادر قد تتعارض، فلا نعتمد بيانات جديدة لمجرد ظهور رابط.
- لماذا فصل الحقائق عن التحرير: ارتباطات المهارات الرسمية لا تعني أن كل مهارة مناسبة للمبتدئ أو أنها تعرّف المجال وحدها؛ اقتراحات البداية موسومة باسم بوصلة.
- لماذا اختبارات متصفح حقيقية: نجاح الحساب لا يكشف وحده فقدان سياق الرجوع أو قبول كسر بسبب التقريب أو قص عنصر على الجوال.
